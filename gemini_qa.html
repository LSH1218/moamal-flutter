2기기 구성 — 여기가 안 되면 아래 전부 막힌다
0/0 ▾
⚠에뮬레이터가 교사다. 교사는 Google 로그인 · 마이크 · QR 표시를 모두 쓰므로 이미지 선택이 중요하다.
⚠PC에 마이크가 없다 (2026-08-25 확인). Windows 마이크 권한은 Allow지만 물리 입력 장치가 연결되어 있지 않다(Realtek 마이크 Present=False, 살아 있는 캡처 장치는 스테레오 믹스뿐). 에뮬은 호스트 입력 장치를 그대로 쓰므로 에뮬 쪽 STT는 어느 라운드에서도 불가능하다. 이 항목은 N/A로 두고 진행한다 — 아래 역할 분담으로 STT 검증은 온전히 커버된다.
ℹ마이크 없이도 STT가 전부 검증되는 이유. 마이크는 항상 공기계 쪽에 있다. 1라운드에서 공기계가 학생이므로 학생 STT가 검증되고, G7에서 공기계가 교사가 되므로 교사 STT가 검증된다. 둘 다 실기기에서 확인되며, 에뮬 STT는 실사용 환경이 아니라 검증 가치가 없다. 대신 각 라운드에서 마이크 없는 쪽은 발화를 만들 수 없다 — 1라운드는 교사 발문(2-8)이, 2라운드는 학생 의견 생성(7-3)이 막힌다. 아래 각 항목에 표시해 두었다.
ℹ현재 환경 실측 (2026-08-25 확인). 교사 Pixel_6 AVD — 이미지 google_apis / API 34 / x86_64, 마이크 hw.audioInput=yes, RAM 2048MB, 411dp. 학생 SM-A305N — Android 11 / API 30 / arm64, 320dp, USB 연결 확인됨. 남은 조치는 두 가지뿐이다 — 런타임 마이크 토글 확인, 그리고 G7 전 후면 카메라 변경.
⚠후면 카메라가 virtualscene이다. 에뮬 카메라가 실제 웹캠이 아니라 가상 3D 방을 비추므로, G7(역할 스왑)에서 에뮬이 학생이 되면 QR 스캔을 할 수 없다. G7 진입 전에 AVD 설정에서 후면 카메라를 Webcam0으로 바꾸거나, 해당 항목만 코드 직접 입력으로 대체한다. 1라운드(에뮬=교사)에서는 에뮬이 QR을 표시만 하므로 문제 없다.
⚠RAM 2048MB. 에뮬 1대는 충분하지만 G5(다중 학생)에서 에뮬 2대를 동시에 띄우려면 빠듯하다. G5를 확장 항목으로 둔 이유 중 하나다. 시도한다면 두 번째 AVD의 RAM을 낮추거나, 실패 시 BLOCKED로 종료한다.
ℹ크로스토크 주의. 같은 방에서 교사(PC 마이크)와 학생(공기계 마이크)이 동시에 녹음하면 서로의 소리를 주워 담는다. 한 번에 한쪽만 녹음을 원칙으로 하고, 크로스토크 자체는 관찰만 기록해 Apollo(실교실)로 넘긴다.
